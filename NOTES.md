# Teaching Notes

- The learner is an experienced software engineer with database and blockchain proficiency.
- Assume general software architecture, data modeling, transactions, APIs, testing, and version-control concepts are familiar.
- Teach by mapping RAP concepts to familiar engineering concepts, then emphasize where SAP semantics differ.
- Prefer causal explanations: what the runtime does, why a construct exists, where logic belongs, and what trade-offs follow.
- Keep syntax reference material compact and searchable; do not make memorization the center of a lesson.
- Use an SAP SD-style process as a coherent example throughout the month.
- Every portfolio artifact should produce evidence useful in an interview: code, tests, diagrams, decisions, demos, or concise explanations.
- Videos should show reasoning and debugging, not only a successful happy-path demo.
