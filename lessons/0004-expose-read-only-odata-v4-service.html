Lesson 4 · 45–60 minutes · Service exposure

Expose the first read-only vertical slice

Put the Sales Order projections behind a protocol-independent service definition, bind that service to OData V4 for a UI client, and prove the request reaches the projected root and child.

Prerequisite gate

Start this lesson only after the tables and all four Lesson 3 CDS entities activate successfully in ADT. A service cannot repair an invalid composition, missing projection source, or broken redirection.

  • ZI_SalesOrderRequest activates.
  • ZI_SalesOrderItem activates.
  • ZC_SalesOrderRequest activates.
  • ZC_SalesOrderItem activates.
  • Data preview can read at least one root and follow its Items association.

The tangible win

Publish a local OData V4 UI endpoint, inspect its metadata, and open a read-only Fiori elements preview containing Sales Order Requests and their Items.

This is the first end-to-end executable evidence in the portfolio: persistence → interface CDS → projection CDS → service definition → OData V4 binding → preview.

Two artifacts, two decisions

ArtifactQuestion it answersDoes not own
Service definition Which CDS entities and names form this business service? OData version, UI/Web API category, or business rules.
Service binding Which client category and communication protocol expose that definition? Entity topology, validations, calculations, or action implementation.

One service definition can support multiple bindings without reimplementing the model. The binding is an ADT repository object with a form-based editor—not ABAP source code.

Predict the read path

Fiori preview→OData V4 binding→service definition→CDS projections→interface CDS→tables

Before opening ADT, say what failure you expect if each layer is missing. This turns activation errors into evidence rather than random trial and error.

Step 1 — Create the service definition

In the package containing the CDS projections, create a Service Definition named ZUI_SALES_ORDER_REQUEST and use this source: 

@EndUserText.label: 'Sales Order Request UI Service'
@ObjectModel.leadingEntity.name: 'ZC_SalesOrderRequest'
define service ZUI_SALES_ORDER_REQUEST {
  expose ZC_SalesOrderRequest as SalesOrderRequests;
  expose ZC_SalesOrderItem    as SalesOrderItems;
}

Expose the projection entities, not the interface entities. The service should honor the consumer boundary you designed in Lesson 3, including the omission of InternalProcessingCode.

Exposing both entities makes the service scope explicit. The root's redirected composition must still target the projected child; the service definition does not recreate that relationship.

Step 2 — Create the OData V4 UI binding

  1. Create a Service Binding from the activated service definition.
  2. Name it ZUI_SALES_ORDER_REQUEST_O4.
  3. Select binding type OData V4 – UI.
  4. Assign the correct package and transport request.
  5. Finish, then activate the binding.

Do not write or copy XML for this step. Repository serializers may represent a binding as XML outside ADT, but developers create and configure the binding with the ADT editor.

Step 3 — Publish and verify in layers

  1. Publish the local service endpoint from the binding editor.
  2. Confirm that both entity sets appear in the binding.
  3. Open the generated service URL and inspect $metadata.
  4. Find SalesOrderRequests and SalesOrderItems.
  5. Verify that the root-to-item navigation targets the projected item type.
  6. Verify that InternalProcessingCode is absent.
  7. Open the Fiori Elements App Preview using the root entity.

Local publication enables the endpoint in the current system. It is not the same as transporting repository objects or deploying a Fiori application to a production launchpad.

Step 4 — Trace one real read

Capture one successful request for the root collection and annotate it using this table:

EvidenceWhat it proves
Binding and generated service URLThe definition is attached to an OData V4 UI protocol.
$metadata entity setsThe service exposes the two projected entities.
Navigation metadataComposition redirection survived service exposure.
Root collection responseThe request reaches projection, interface model, and persistence.
Fiori previewA metadata-driven client can consume the service.

Record the actual generated URLs from your system. Do not memorize or invent a URL pattern because service paths vary by binding and system.
