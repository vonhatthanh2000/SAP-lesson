A ABAP Core (RICEFW)

Reports · Interfaces · Conversions · Enhancements · Forms · Workflow + core ABAP
1.What does RICEFW stand for?
Reports, Interfaces, Conversions, Enhancements, Forms, Workflow — the six categories used to classify and scope custom (Z) developments in an implementation. It is the standard framework teams use to size and track WRICEF objects.
2.Difference between CL_SALV_TABLE and REUSE_ALV_GRID_DISPLAY?
CL_SALV_TABLE is the modern, fully OO ALV (via cl_salv_table=>factory) — clean and quick for display-only lists, field catalog auto-derived. The classic REUSE_ALV_GRID_DISPLAY / CL_GUI_ALV_GRID is older but required for editable cells, rich events and deep control that SALV does not expose.
3.Classical vs Interactive vs ALV reports?
Classical uses WRITE list processing (static). Interactive adds drill-down via AT LINE-SELECTION / HIDE. ALV renders a grid with sorting, filtering, totals, export and layout variants — the standard today.
4.Standard, Sorted and Hashed internal tables — when to use each?
Standard: index access, linear search, duplicates allowed. Sorted: kept sorted by key, binary search, ideal for range/partial-key reads. Hashed: unique key, hash access (~O(1)), no index — best for repeated single-record lookups in loops.
Pro-tip: Replacing a nested READ TABLE on a standard table with a hashed/sorted table is one of the highest-impact loop optimizations you can quote.
5.Key ABAP SQL performance rules?
Select only needed fields (avoid SELECT *), always filter on indexed fields, never SELECT inside a LOOP, prefer JOIN / CDS over multiple round-trips, and read once into an internal table then process in memory.
6.Pitfalls of FOR ALL ENTRIES?
It returns nothing if the driver table is empty (worse: drops the whole FAE condition and can full-scan), and it removes duplicates from the result. Always check the driver isn't empty, delete duplicates, and include key fields in the field list. A DB JOIN/CDS is usually faster.
7.BAPI vs RFC vs BDC for interfacing?
BAPI = released, stable, RFC-enabled FM with business logic and a documented interface. RFC = any remote-enabled FM. BDC = screen-level batch input (no API) when no BAPI exists. Preference: BAPI > RFC > BDC.
8.Structure of an IDoc?
Control record (EDIDC — sender/receiver, message & basic type), Data records (EDID4 — segments/fields), Status records (EDIDS — processing history). Defined by a Basic Type + Message Type, used in ALE/EDI.
9.Inbound vs Outbound IDoc processing?
Outbound: application generates the IDoc, it flows through a port to the partner. Inbound: the IDoc is received and a process code / FM posts it into SAP. Partner profiles (WE20) drive both directions.
10.Call Transaction vs Session method in BDC?
Call Transaction runs synchronously with your own error handling (fast, immediate). Session (SM35) queues records for robust, logged batch processing. Modes: A (all screens), E (errors only), N (no display).
11.Which tools for data conversion / migration?
LSMW (config-driven, multiple techniques), BDC (screen recording), BAPI (cleanest, API-based), and in S/4HANA the Migration Cockpit (LTMC / LTMOM). Prefer BAPI or Migration Cockpit.
12.What is the Enhancement Framework?
It unifies non-modification techniques: implicit enhancements (predefined spots at start/end of FMs/methods/forms), explicit enhancement points/sections, classic user/customer exits (SMOD/CMOD), and BAdIs (OO). Enhancements are upgrade-safe; modifications are not.
13.Classic BAdI vs new (kernel) BAdI?
Classic BAdI (SE18/SE19) is object-based with single/multiple use and filters. New/kernel BAdI sits in an enhancement spot, is faster, supports a fallback class, and integrates with the switch framework.
14.User exit vs BAdI?
A user exit is an empty subroutine in a SAP include (e.g. MV45AFZZ in SD) — procedural, limited. A BAdI is an OO interface allowing multiple, filter-based implementations — more flexible, the modern choice.
15.SAPscript vs SmartForms vs Adobe Forms?
SAPscript: oldest, client-dependent. SmartForms: graphical, generates its own FM, no client dependency. Adobe Forms: interactive, print-quality PDF, offline scenarios — strategic on S/4.
16.Core concept of SAP Business Workflow?
An event triggers a workflow whose tasks/steps are routed to agents by rules; a container carries the data. Model in SWDD, monitor in SWI1. Automates approvals and multi-actor processes.
17.Field-symbols vs data references?
Field-symbols (ASSIGN) point to existing memory — no copy, great for LOOP ... ASSIGNING. Data references (REF, CREATE DATA) create/address dynamic objects for generic programming.
18.Four pillars of OOP in ABAP?
Encapsulation, Inheritance (single, INHERITING FROM), Polymorphism (redefinition / interfaces), Abstraction (abstract classes & interfaces). Multiple interface implementation, single inheritance.
19.Global vs local class?
A global class (SE24 / class pool) is repository-wide and reusable. A local class is defined inside one program and only visible there — good for helper logic.
20.Class-based exception handling?
TRY … CATCH … CLEANUP … ENDTRY with classes rooted at CX_ROOT. Categories: CX_STATIC_CHECK (declare/handle), CX_DYNAMIC_CHECK, CX_NO_CHECK (runtime). Replaces relying on SY-SUBRC.
21.How do you debug efficiently?
Session/external breakpoints, watchpoints (stop on variable change), inspect call stack and internal tables, conditional breakpoints in loops. /h starts the debugger; checkpoints help in background/RAP.
22.Which performance-analysis tools do you use?
ST05 (SQL/RFC/enqueue trace), SAT/SE30 (runtime trace), ST12 (single-transaction combined trace), SQLM/SWLT (SQL monitor), and ATC / Code Inspector for static findings.
23.How does SAP locking work?
Define a lock object in SE11 (EZ*) generating ENQUEUE_/DEQUEUE_ FMs. These are logical (SAP) locks in the enqueue server, independent of DB locks, to serialize access to business objects.
24.V1 vs V2 update, and update task?
V1: synchronous/time-critical (document posting). V2: deferred, non-critical (statistics). Register with CALL FUNCTION … IN UPDATE TASK; COMMIT WORK triggers execution.
25.Database LUW vs SAP LUW?
A DB LUW is one atomic DB transaction. An SAP LUW bundles several DB LUWs (often via update task) into one business transaction finalized by a single COMMIT WORK — all-or-nothing consistency.
26.Modularization units in ABAP?
Include, Subroutine/FORM (procedural, obsolete in OO), Function Module (reusable, remote-enabled), Method (OO — preferred). Clean ABAP favors small methods.
27.Transparent vs pooled vs cluster tables?
Transparent: 1:1 with a physical DB table (standard). Pooled/cluster: many logical tables in one physical table to save space — legacy, mostly gone in S/4HANA.
28.Table buffering types?
Single-record, generic (by leading key fields), full. Use for small, read-mostly config tables; avoid on frequently changed or very large tables.
29.When do you create a secondary index?
When large tables are frequently filtered on non-primary-key fields. It speeds reads but slows inserts/updates, so index only columns that genuinely improve selective access.
30.What is 'code pushdown' and how do you enforce quality?
Code pushdown = do heavy data work in the DB (CDS, AMDP) not ABAP loops — key for HANA. Enforce quality with ATC / Code Inspector, ABAP Unit tests and Clean ABAP guidelines.
31.SELECT SINGLE vs SELECT ... UP TO 1 ROWS?
SELECT SINGLE reads one row by (ideally full) key — with a partial key the DB returns an arbitrary match. UP TO 1 ROWS … ORDER BY lets you control which row (e.g. latest). Use SINGLE with full key; UP TO 1 ROWS + ORDER BY when you need a specific first row.
32.TYPE vs LIKE?
TYPE refers to a data type (DDIC/local/built-in). LIKE refers to an existing data object, inheriting its type. Prefer TYPE in modern ABAP; use LIKE only to mirror an existing variable.
33.Prerequisites for BINARY SEARCH and DELETE ADJACENT DUPLICATES?
Both need the table sorted by the relevant key first. BINARY SEARCH on unsorted data misses hits; DELETE ADJACENT DUPLICATES only removes consecutive duplicates. With sorted/hashed tables, key access is automatic — no BINARY SEARCH needed.
34.What are internal-table secondary keys (7.40+)?
Additional sorted or hashed keys defined on a standard table to speed alternate access paths (READ/LOOP … USING KEY) without a second table. Trades memory/maintenance for read speed.
35.When do you use COLLECT?
To aggregate numeric fields by a (non-numeric) key: if the key exists it sums the numeric components, otherwise inserts. Cleaner than READ+MODIFY for summing by key — ideal for building totals.
36.SAP memory vs ABAP memory?
SAP memory (SPA/GPA, SET/GET PARAMETER) is cross-session, user-wide (carry values between transactions). ABAP memory (EXPORT/IMPORT … TO MEMORY ID) lives within one internal session/call stack (e.g. passing data to CALL TRANSACTION).
37.How does AUTHORITY-CHECK work?
It checks the user against an authorization object's fields; SY-SUBRC = 0 means authorized. Custom reports/transactions must add explicit checks — the object is defined in SU21 and granted via PFCG roles. A start-of-transaction check alone isn't enough for sensitive data.
38.Message types E, W, I, S, A, X?
E error (stops), W warning, I information (popup, continues), S success (status line, next screen), A abort (terminates), X exit/dump. In background, E behaves like A.
39.Key selection-screen events?
INITIALIZATION (defaults before display), AT SELECTION-SCREEN (validate input), AT SELECTION-SCREEN ON <field> and OUTPUT (PBO). Variants store reusable input sets for scheduling.
40.sRFC vs aRFC vs tRFC vs qRFC?
sRFC: synchronous (caller waits). aRFC: asynchronous/parallel with callback. tRFC: transactional, executed once via a queue table. qRFC: queued tRFC with guaranteed ordering (SMQ1/SMQ2). Choose by reliability/ordering needs.
41.Why call BAPI_TRANSACTION_COMMIT?
BAPIs don't commit internally — you must call BAPI_TRANSACTION_COMMIT (or ROLLBACK on error) to close the LUW. This lets you chain several BAPIs in one transaction. Use WAIT = 'X' to ensure the update finished before reading back.
42.IDoc status codes & how to reprocess?
Outbound e.g. 03 (passed to port), 12 (dispatched); inbound 53 (posted OK), 51 (application error), 64 (ready to post). Reprocess errored IDocs via BD87, or edit/test with WE19. Status 51 usually means a business validation failed.
43.What are change pointers?
For master-data distribution, SAP logs field changes in change pointers (BDCP/BDCPV). Activate per message type (BD50) and field (BD52), then RBDMIDOC generates delta IDocs. Lets you send only what changed.
44.Number ranges (SNRO) and buffering?
Define number range objects/intervals; NUMBER_GET_NEXT fetches the next value. Buffering boosts performance but causes gaps and non-sequential numbers — fine unless gap-free numbering is legally required.
45.Background jobs — how do you schedule and monitor?
Define in SM36 (job → steps → start condition: time, event, after job, periodic); monitor logs/spool in SM37. Event-driven jobs trigger on SAP_END_OF_JOB or custom events (BP_EVENT_RAISE). Use job classes for priority.
46.What is AMDP and when do you use it?
ABAP-Managed Database Procedure — SQLScript written inside an ABAP method (BY DATABASE PROCEDURE), executed on HANA. Use for complex set/loop logic CDS can't express while keeping pushdown; it's DB-specific and heavier than CDS.
47.ABAP proxy vs RFC/BAPI for interfacing?
A proxy (generated from a service interface/WSDL) exchanges structured XML and is standard for PI/PO / web-service style, loosely-coupled integration. RFC/BAPI is tighter, function-call style, best for synchronous SAP-to-SAP. Proxies decouple contract from implementation.
48.What is the Table Maintenance Generator (SM30/SE54)?
It generates a standard maintenance dialog (SM30) for a custom table so functional users maintain config without a program. Assign a maintenance view + auth group, add events for validation. Backbone of Customizing-table-driven design.
49.How do you unit-test ABAP?
With ABAP Unit — local test classes (FOR TESTING) using cl_abap_unit_assert. Isolate dependencies via test seams / dependency injection / the test-double framework. Essential for RAP and Clean ABAP; runs via ATC.
50.SUBMIT vs CALL TRANSACTION vs CALL FUNCTION?
SUBMIT runs a report program (with selection screen/variant, optionally AND RETURN). CALL TRANSACTION runs a T-code (optionally with BDC data). CALL FUNCTION executes a function module (local/remote). Pick by the reusable unit type.

B CDS View

Core Data Services — the data-modeling backbone of S/4HANA
1.What is a CDS view? ABAP CDS vs HANA CDS?
CDS = Core Data Services, a semantic data model in DDL pushed to the DB. ABAP CDS is activated in the ABAP dictionary (transportable, DB-agnostic, framework-integrated) and recommended for S/4; HANA CDS (.hdbdd) is HANA-native.
2.CDS view vs classic DDIC view?
CDS supports associations, annotations, parameters, expressions, aggregations, unions and built-in client handling — none offered by a classic DDIC view. CDS is also the base for OData, RAP and analytics.
3.What are annotations and why do they matter?
Metadata (prefixed @) steering framework behavior — @OData.publish, @UI.*, @Analytics.dataCategory, @ObjectModel, @Semantics. One artifact declaratively drives UI, OData and analytics.
4.Association vs JOIN?
A JOIN always executes. An association is a reusable 'join-on-demand' resolved only when its path is used — lighter, and it exposes navigation for OData/Fiori.
5.What is the Virtual Data Model (VDM)?
A layering convention: Basic/Interface views (close to tables, reusable), Composite (combine), Consumption (exposed to UI/OData). Keeps models clean and upgrade-stable.
6.@OData.publish:true vs Service Definition + Binding?
@OData.publish auto-generates a service fast but with little control. A Service Definition + Binding (RAP way) exposes selected entities, lets you pick V2/V4 and version cleanly — preferred for production.
7.How do CDS parameters work?
Declared with with parameters p_date : abap.dats and used in SELECT/WHERE (e.g. currency conversion by date). Values are supplied at consumption via OData, another CDS, or ABAP SQL.
8.What makes a CDS view 'analytical'?
Annotations like @Analytics.dataCategory: #CUBE/#DIMENSION, measures with @DefaultAggregation, exposure as a query. Feeds the Analytical List Page and analytical apps.
9.How is authorization handled in CDS?
Via DCL — an access-control object restricting rows, usually mapping to PFCG through aspect pfcg_auth. It enforces row-level security automatically for every consumer.
10.How do you extend a CDS view without modifying it?
Use an extend view / EXTEND VIEW ENTITY to append custom fields (extend the underlying append structure for persisted ones) — leaving the SAP object untouched, core to Clean Core.
11.What is association cardinality and why does it matter?
Declared as association [min..max] to _Target on … (e.g. [0..1], [1..*]). It tells the framework/OData the multiplicity (to-one vs to-many) and influences join behavior. Wrong cardinality causes unintended row multiplication.
12.What is $projection?
In a projection/consumption view, $projection references the current view's own elements (e.g. in association ON-conditions or filters), decoupling from the source alias. Used heavily in RAP projection views.
13.CDS View Entity vs classic DDIC-based CDS view?
DEFINE VIEW ENTITY (new) has no separate DDIC SQL view, stricter syntax, better default client/annotation handling, and is SAP's recommendation. The old DEFINE VIEW generates an underlying SQL view. New work should use view entities.
14.CASE expressions in CDS?
Simple (CASE field WHEN…) and searched (CASE WHEN cond THEN…) expressions derive columns (e.g. map status to a flag/text), executed in the DB. Keep them readable — deep nesting hurts maintainability.
15.What is CAST used for?
CAST( field AS type ) converts data types — e.g. typing an amount to a currency field, aligning types in a UNION, or attaching @Semantics. Use PRESERVING TYPE where needed.
16.UNION vs UNION ALL?
UNION removes duplicate rows (extra cost); UNION ALL keeps all (faster). Field lists must match in number/type/order. Prefer UNION ALL unless de-duplication is truly required.
17.Aggregations and GROUP BY in CDS?
Use SUM/MIN/MAX/AVG/COUNT with GROUP BY; every non-aggregated selected field must be in GROUP BY. For analytics add @DefaultAggregation on measures so consumers re-aggregate dynamically.
18.Currency/quantity handling and @Semantics?
Amounts need @Semantics.amount.currencyCode: 'CurrencyField' and quantities @Semantics.quantity.unitOfMeasure so UIs format correctly; conversion uses currency_conversion( ) with a rate date.
Pro-tip: Missing @Semantics on amounts is a classic 'Fiori shows the number wrong / no currency' bug — an easy point to score.
19.What are CDS session variables?
$session.user, $session.client, $session.system_date, $session.system_language let a view react to runtime context (e.g. filter by current user, use today's date) — pushed down to the DB.
20.How do you expose language-dependent texts?
Via a text association: a text view annotated with @Semantics.text/@ObjectModel.text.element, associated from the master view so UIs show the description in the user's language automatically.
21.Composition vs Association?
A composition is a parent-child association expressing existential dependency (child can't exist without parent) — the backbone of RAP hierarchies (header→item), enabling create-by-association and cascade. A plain association is a non-owning reference.
22.What is a CDS Table Function?
A CDS entity whose implementation is an AMDP method (SQLScript). Use when logic needs procedural steps DDL can't express, while still exposing a CDS-consumable entity. HANA-specific — use sparingly.
23.What is a Metadata Extension?
@Metadata.allowExtensions:true lets you keep UI/annotation logic in a separate .ddlx file with @Metadata.layer (core/partner/customer). Keeps the data model clean, layered and extensible.
24.How is client handling done in CDS?
View entities are client-dependent by default and add the client implicitly (@ClientHandling controls it). You don't select MANDT manually — the framework manages it, unlike classic views.
25.Deep-dive: how does DCL access control work?
A DCL role (define role … grant select on view where …) restricts rows; conditions can inherit from other views (inheriting conditions from entity) and map to PFCG via aspect pfcg_auth. It applies centrally to every consumer (OData, ABAP SQL).
26.Does CDS support hierarchies?
Yes — define a parent-child hierarchy (hierarchy( … )) over a self-association for tree displays and rollups (e.g. cost centers), consumed by hierarchical Fiori controls/queries.
27.What is a Consumption view's role?
The top VDM layer exposed to a service — stable, annotated for UI/analytics, bound via Service Definition/Binding or @OData.publish. Separating it from interface views shields consumers from model changes.
28.What does @EndUserText.label do?
Supplies field/view labels shown on the UI and in metadata; with element annotations it drives usable OData/Fiori without ABAP. Good labeling is part of a professional, self-documenting deliverable.
29.How do you extend a view entity for custom fields?
EXTEND VIEW ENTITY … WITH … adds fields/associations without modifying the original (needs an extension include on the table for persisted fields). A core Clean-Core extensibility technique.
30.CDS performance best practices?
Push filtering/aggregation to the DB, avoid deep nesting and redundant views, prefer associations over eager JOINs, select only needed fields, put selective conditions in ON/WHERE, and inspect the generated SQL with the trace / CDS analyzer.

C Fiori (basics)

SAP's role-based UX layer on top of OData
1.What is SAP Fiori and its design principles?
Fiori is SAP's UX design language and app family. Principles: role-based, adaptive (responsive), coherent, simple, delightful — focusing on the user's actual tasks.
2.Fiori Elements vs Freestyle SAPUI5?
Fiori Elements generate the UI from CDS/OData annotations (little/no JS, consistent, upgrade-friendly). Freestyle is hand-coded SAPUI5 for full control. Rule: Elements first, freestyle only when needed.
3.Fiori runtime architecture?
Launchpad (FLP) hosts tiles → the SAPUI5 app runs in the browser → calls an OData service via the Gateway (/IWFND) → reads the backend (CDS/SEGW). Embedded or Front-End-Server deployment.
4.Catalog, Group, Tile, Target Mapping?
Catalog = apps assigned to roles; Group = tile arrangement; Tile = visual entry point; Target Mapping = semantic object + action resolving which app launches. A missing one is the classic 'tile not showing' cause.
5.OData V2 vs V4 in Fiori?
V4 is leaner, supports richer analytics and draft, and is required by newer Fiori Elements V4 templates; V2 remains widespread. RAP service bindings let you choose either.
6.Main Fiori Elements floorplans?
List Report + Object Page, Analytical List Page (ALP), Overview Page (OVP), Worklist. The floorplan is driven by annotations, not code.
7.Which UI annotations drive Fiori Elements?
@UI.lineItem (columns), @UI.selectionField (filters), @UI.identification (object-page fields), @UI.facet (sections), @UI.headerInfo. They live in the CDS/metadata extension layer.
8.Embedded vs hub (central) deployment?
Embedded runs Gateway/FLP on the S/4 system (simpler, fewer hops). Hub/central uses a separate Front-End Server for multiple back-ends (security isolation, multi-system landscapes).
9.A Fiori app doesn't show — how do you troubleshoot?
Check in order: role/catalog (PFCG), target mapping & semantic object, OData service activation (/IWFND/MAINT_SERVICE), and gateway errors (/IWFND/ERROR_LOG). Usually authorization or an inactive service.
10.SAPUI5 MVC essentials?
Model (OData/JSON), View (XML), Controller (events), tied by Component.js and manifest.json. Reuse via fragments; customize standard apps via extension points, never by modifying SAP code.

D ABAP RAP

ABAP RESTful Application Programming model — the Clean Core dev standard
1.What is RAP and how does it relate to BOPF?
RAP builds OData services and business objects using CDS + a behavior model. It is the successor to BOPF, cloud-ready and Clean-Core aligned — standard for S/4HANA Cloud and on-prem extensions.
2.Managed vs unmanaged scenario?
In a managed BO the framework handles persistence (CRUD, keys, save). In an unmanaged BO you implement create/update/delete/save yourself — for wrapping legacy tables/logic.
3.Main building blocks of a RAP BO?
A CDS data model (interface + projection view), a Behavior Definition (BDEF), a Behavior Implementation (handler/saver class), and a Service Definition + Binding exposing OData V2/V4.
4.What can you declare in a Behavior Definition?
Field characteristics (readonly, mandatory), operations (create/update/delete), associations, actions, determinations, validations, locking, authorization and draft.
5.What is draft handling?
Persists an in-progress edit in a draft table so users can leave/resume and stay consistent across devices. Fiori Elements consumes it automatically once the BO is with draft;.
6.Determination vs Validation?
A determination automatically derives/changes data on a trigger (modify/save) — e.g. compute a total. A validation checks consistency and raises messages without changing data — e.g. reject an invalid status.
7.Types of RAP actions?
Instance (on a specific entity), static (on the entity type, no key), factory (create instances). Actions can take parameters and return results, and appear as Fiori buttons.
8.What is EML?
Entity Manipulation Language — ABAP syntax (READ/MODIFY/COMMIT ENTITIES) to read and change RAP BOs directly, e.g. for tests, jobs or BO-to-BO calls.
9.Managed BO but data must go to legacy tables — options?
Use a managed BO with additional save (saver writing to legacy tables), or unmanaged save / unmanaged lock when persistence is fully custom. Late numbering assigns keys at save.
10.How does RAP support Clean Core / extensibility?
Extend the CDS model and BDEF (behavior extension) instead of modifying the BO, and consume only released APIs. Custom logic lives in your package — keeping the core upgrade-safe.
11.Interface (base) view vs Projection view — why two?
The interface view models the data and defines compositions/associations (stable, reusable). The projection view exposes a tailored subset (with @UI, $projection) to a specific service, so several services project the same BO differently.
12.Behavior Definition vs Behavior Projection?
The BDEF defines the full behavior on the interface view. The behavior projection (projection; use action…) selectively exposes that behavior for a service — you can't add new logic in the projection, only expose it.
13.Static vs dynamic feature control?
Feature control enables/disables operations/actions/fields. Static is fixed in the BDEF; dynamic is computed at runtime in get_instance_features / get_global_features (e.g. disable 'Approve' unless status = submitted). Dynamic needs the features : instance annotation.
14.How does field control work?
Sets readonly/mandatory. Static field control is declared in BDEF (field (mandatory, readonly)); dynamic is evaluated in get_instance_features returning %control per field — e.g. mandatory only for a certain category.
15.How is authorization implemented in RAP?
Global authorization (get_global_authorizations) gates whole operations (e.g. create); instance authorization (get_instance_authorizations) gates per-record actions/update/delete based on the data. Combine both for full coverage.
16.Early vs late numbering?
Early assigns the key during CREATE. Late assigns keys only at save (adjust_numbers), typically from a number range at commit to avoid gaps/collisions — needs the late numbering addition in BDEF.
17.Draft-specific actions and %is_draft?
Draft BOs get standard Edit, Activate, Discard, Resume, Prepare actions. %is_draft distinguishes draft vs active instances in EML/logic; draft-time checks bind to the Prepare determine action.
18.What are Side Effects (@Sideeffects)?
Declared in the projection to tell Fiori which fields/entities to reload after a change/action (e.g. changing quantity recalculates total) — no full refresh, better UX and fewer round-trips.
19.What is create-by-association?
With a composition, you create children through the parent (CREATE BY \_Assoc in EML or 'Create' on a sub-object page) and the framework links them by parent key. Only compositions (ownership) support it.
20.EML result structures — mapped, failed, reported?
failed = keys that failed with a cause; reported = messages per key; mapped = mapping of %cid to assigned keys on create. Always check failed before COMMIT ENTITIES; use reported to surface messages.
21.How does RAP do concurrency control?
Optimistic locking via an ETag field (e.g. last-changed timestamp) declared in BDEF (etag master LastChangedAt). The framework rejects an update if the ETag changed since read, preventing lost updates.
22.What are virtual elements?
CDS fields not persisted, calculated at runtime via ABAP (@ObjectModel.virtualElement + a calculation class). Use for values needing complex ABAP logic that still must appear in the service — mind performance (avoid sorting/filtering on them).
23.What is a RAP custom query?
For unmanaged/analytical reads you implement a query class (IF_RAP_QUERY_PROVIDER) that fills results from the request (filters, paging, sorting) — e.g. reading a remote system or custom logic instead of a CDS-backed table.
24.Business events in RAP?
A BO can raise business events (raise entity event in BDEF + EML) published via Event Mesh for loosely-coupled, event-driven integration (e.g. 'PermitApproved') — aligns with side-by-side / Clean Core.
25.What is strict mode (strict(2))?
Activates the latest syntax checks and best-practice rules (mandatory implementations, correct action/feature definitions), ensuring the BO is cloud-/upgrade-ready. New BOs should always be strict(2).
26.What is a precheck?
A precheck validates a modification before the framework writes it to the buffer (ahead of determinations/validations), rejecting invalid changes early — e.g. block a value that must never enter the transactional buffer.
27.Explain the RAP save sequence / additional save.
Phases: finalize → check_before_save → adjust_numbers (late numbering) → save → cleanup. Additional save (saver) writes to extra/legacy tables alongside managed persistence; save_modified exposes the changed instances.
28.Managed vs unmanaged lock?
Managed lock is handled by the framework using the root key. Unmanaged lock (lock master unmanaged) means you implement the lock yourself (e.g. reuse an existing enqueue) — for legacy-wrapping scenarios.
29.How should one RAP BO call another?
Via EML (MODIFY/READ ENTITIES) rather than writing the other BO's tables directly — keeping business logic encapsulated in the owning BO, ensuring consistency and reuse. Use IN LOCAL MODE to bypass the target's auth/feature checks when appropriate.
30.How do you test a RAP BO?
With ABAP Unit driving the BO through EML, plus the RAP BO test double framework (cl_abap_behv_test_environment) to isolate persistence and dependencies — so tests run without touching real tables.

E CPI — Cloud Integration

SAP Integration Suite's iPaaS for cloud & hybrid integration
1.What is CPI / Cloud Integration?
The cloud integration capability of SAP Integration Suite on BTP — a managed iPaaS with prebuilt content, the strategic successor to PI/PO for cloud/hybrid landscapes.
2.What is an iFlow?
An Integration Flow — a BPMN-style model going sender → steps → receiver, defining adapters, mappings, routing and error handling, designed in the Integration Suite web tooling.
3.Common CPI adapters?
HTTPS, SOAP, OData, IDoc, SFTP/FTP, JMS, AMQP, Mail, SuccessFactors, and ProcessDirect for internal iFlow-to-iFlow calls.
4.Content Modifier, Message Mapping, Groovy script?
Content Modifier sets headers/properties/body; Message Mapping transforms structures graphically; Groovy/JS handles logic the standard steps can't — reading/writing headers, properties and payload.
5.Splitter, Gather, Aggregator?
Splitter breaks a bulk message into parts (general/iterating), Gather/Join recombines branches, Aggregator collects related messages over time into one — essential for batch and B2B.
6.How do you handle errors in an iFlow?
Add an Exception Subprocess, set a meaningful error payload/status, use retry (JMS with dead-letter), and raise alerts. Design idempotency so retries don't double-post.
7.How is security/credentials managed?
Through Security Material — OAuth2 client credentials, user credentials, and client certificates / keystores. Sensitive values are secure parameters, never hard-coded.
8.Request-Reply vs Content Enricher vs Poll Enrich?
Request-Reply: synchronous call, continue with response. Content Enricher: merge an external lookup into the message. Poll Enrich: fetch from a source (e.g. SFTP) at a point in the flow.
9.Value Mapping vs Message Mapping?
Message Mapping transforms structure. Value Mapping converts code values between systems (e.g. country codes) via a maintained table — reusable across iFlows.
10.How do you monitor CPI, and how does it differ from PI/PO?
Via the Message Processing Log (MPL) and trace-level logging. Unlike PI/PO (on-prem, often dual-stack, self-managed), CPI is a cloud, SAP-managed service with prebuilt content and simpler scaling.
Pro-tip: Frequent gotcha: a custom header silently dropped until Allowed Headers = * is set on the sender adapter — mentioning such debugging signals hands-on experience.
11.Headers vs Exchange Properties?
CPI runs on Apache Camel. Headers travel with the message and may be sent to the receiver; Exchange Properties live only inside the iFlow runtime (not sent out). Use properties for internal state, headers when the value must reach the receiver.
12.What is the ProcessDirect adapter for?
An in-tenant adapter that calls another iFlow directly (no network hop), letting you split large integrations into reusable, independently deployable flows (e.g. a shared error-handling or mapping flow). Improves modularity.
13.Why use JMS queues?
Asynchronous, transactional in-tenant queues that decouple sender/receiver, enable retry and store-and-forward, and provide dead-letter handling for persistently failing messages. Key for reliability and load leveling; consumes tenant queue resources.
14.What are externalized parameters?
Config values (URLs, credential names, paths) marked externalized so they're set per environment (DEV/QA/PRD) at configuration time without editing the iFlow — supporting clean transports.
15.Data Store vs Variables?
Data Store persists messages/payloads (write/get/select/delete) for later processing or de-duplication; Variables (global/local) persist small values (e.g. last-run timestamp) across executions — used for delta polling and stateful patterns.
16.Router vs Filter?
A Router does content-based routing — evaluates conditions (XPath) and sends the message down the matching branch (with a default). A Filter extracts a portion of the payload, discarding the rest. Router = choose path; Filter = trim content.
17.Encryption/signing and OAuth inbound vs outbound?
CPI supports PGP encryption/decryption and digital signing/verification for B2B, plus TLS. OAuth is used inbound (protecting the iFlow endpoint) and outbound (obtaining tokens to call receivers) — configured via Security Material.
18.B2B / Partner Directory and EDI?
The Integration Suite B2B capability manages trading partners via the Partner Directory and processes EDIFACT / ANSI X12 over AS2/SFTP, mapping to/from XML — for supplier/customer electronic document exchange.
19.API Management vs Cloud Integration?
Cloud Integration (CPI) does message mediation/transformation (iFlows). API Management publishes, secures, rate-limits and monetizes APIs (proxies, policies, developer portal). Complementary capabilities within Integration Suite.
20.How do you transport iFlows across tenants?
Via CTS+, the Transport Management Service (TMS) on BTP, or manual MTAR/package export-import. Externalized parameters keep environment-specific values out of the transported artifact.

F SAP BTP

Business Technology Platform — extend, integrate, innovate
1.What is SAP BTP?
The Business Technology Platform — SAP's PaaS uniting app development, integration, data & analytics, AI and automation. Where you build side-by-side extensions and integrations around the digital core.
2.Which runtime environments does BTP offer?
Cloud Foundry (polyglot apps), Kyma (managed Kubernetes), the ABAP environment (Steampunk), and legacy Neo (deprecated). Choose by skillset/workload.
3.In-app vs side-by-side extensibility?
In-app extensions live inside S/4 (key-user, developer extensibility). Side-by-side apps run on BTP calling S/4 via released APIs — preferred for larger, decoupled custom apps and Clean Core.
4.Explain the BTP account model.
A Global Account holds entitlements; it contains Subaccounts (per region/project/stage); in Cloud Foundry a subaccount has Spaces. Entitlements/quotas allocate services.
5.How does BTP connect securely to on-prem S/4?
The Cloud Connector establishes a secure reverse tunnel on-prem↔subaccount; the Connectivity and Destination services define the target system and its authentication.
6.How is authentication/authorization handled?
XSUAA (OAuth2, issues JWTs) with app roles grouped into role collections, backed by an IdP (IAS/IPS or corporate). Apps validate the token and check scopes.
7.What is the ABAP Environment (Steampunk)?
ABAP-as-a-service on BTP for side-by-side ABAP apps using RAP and released APIs. Embedded Steampunk brings the same restricted, cloud-ready ABAP model inside S/4HANA Cloud.
8.What is CAP?
The Cloud Application Programming model — an opinionated framework (Node.js/Java) built on CDS for rapidly building services and OData APIs on BTP, with built-in persistence, auth and best practices.
9.Which BTP services matter for an integration/extension consultant?
Integration Suite (CPI), Build Apps / Work Zone, Workflow & Process Automation, Event Mesh, Destination/Connectivity, HANA Cloud — mixed to deliver side-by-side scenarios.
10.What is the Clean Core strategy and BTP's role?
Keep the S/4 core standard — no modifications, only released extension points/APIs — and move substantial custom logic to BTP side-by-side. Makes upgrades faster, cheaper and lower-risk; a top talking point on modern S/4 projects.

G PI / PO

Process Integration / Orchestration — the on-premise ESB
1.What is SAP PI/PO?
SAP Process Integration / Orchestration — on-premise middleware/ESB for A2A and B2B integration, mediating, routing and transforming messages between SAP and non-SAP systems.
2.Describe the PI/PO architecture.
Design in the ESR, configuration in the Integration Directory (ID), runtime in the Integration/Adapter Engine (AEX); the SLD holds the landscape and the RWB is used for monitoring.
3.Key ESR (design-time) objects?
Data Types, Message Types, Service Interfaces (in/out), and Message & Operation Mappings — the message contracts and transformations, independent of any system.
4.Key Integration Directory (config-time) objects?
Communication Channels, sender/receiver agreements, receiver & interface determination — or, on single stack, the consolidated Integrated Configuration (ICO). They bind design objects to concrete systems.
5.Dual stack vs single stack?
Dual stack (classic PI) ran ABAP + Java. Single stack (AEX — Java only, 'PO') is leaner, easier to maintain and SAP's recommendation; it uses the Integrated Configuration.
6.Which mapping types are available?
Graphical (message) mapping, XSLT, Java, ABAP mapping. Graphical covers most cases; XSLT/Java for complex transformations, chainable in an operation mapping.
7.When do you use ccBPM/BPM?
For stateful, multi-message orchestration — collecting/correlating messages, wait steps, splits/merges. It adds overhead, so use only when stateless routing can't express the process.
8.Common PI/PO adapters?
IDoc, File/FTP/SFTP, SOAP, REST, JDBC, RFC, Proxy, Mail. The adapter converts between the external protocol and PI's internal XML message.
9.Proxy vs adapter-based communication?
Proxy (ABAP/Java) generates message interfaces in the application system and uses the native XI protocol — efficient, no adapter. Adapter-based communication converts external formats at the Adapter Engine.
10.How do you monitor PI/PO, and what's the path to CPI?
Use message monitoring, channel monitoring and the RWB / component monitoring to trace/reprocess. SAP positions Integration Suite (CPI) as the successor, with a migration assessment/tooling to move iFlows to the cloud.
