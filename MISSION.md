# Mission: Become Interview-Ready for SAP RAP Development

## Why
Transition from database and blockchain engineering into SAP development by becoming credible for a mid-level SAP RAP role. Build a public portfolio that proves the ability to reason about RAP architecture and implement realistic business logic, using an SAP SD-style sales-order scenario.

## Success looks like
- Explain how a request flows through CDS, a RAP business object, EML, an OData V4 service, and a Fiori elements UI.
- Design and implement a portfolio-grade transactional RAP application with validations, determinations, actions, authorization, draft behavior, and automated tests.
- Explain design choices and trade-offs for managed versus unmanaged RAP and relate the solution to an SD business process.
- Publish a concise video series and supporting repository that demonstrate engineering judgment, not copied syntax.
- Handle a realistic RAP technical interview and clearly distinguish demonstrated ability from topics that require deeper production experience.

## Constraints
- One month to produce an interview-ready portfolio.
- Prior experience: proficient in databases and blockchain; basic ABAP syntax already learned; currently learning RAP.
- Prioritize architecture, runtime behavior, business logic, debugging, and design trade-offs over syntax memorization.
- Use SAP official documentation and first-party repositories under `SAP-samples` as primary sources.
- Use SAP SD as the example domain without attempting to master the entire SD functional module.

## Out of scope
- Exhaustive ABAP syntax study.
- Full SAP SD functional-consultant certification coverage.
- Claiming production experience that the portfolio cannot demonstrate.
- Broad coverage of unrelated SAP technologies during the one-month sprint.
